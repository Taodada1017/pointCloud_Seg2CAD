## 一、系统总览

整个系统的目标：**给定一个室内场景的LiDAR彩色点云 + 多视角图像 + 相机位姿，自动输出带真实尺度的2D CAD平面图。**

```
输入:
  ├── colorized.pcd      (3500万个3D彩色点)
  ├── RGB/left/*.jpg      (70张左相机图像, 1600×1600)
  ├── RGB/right/*.jpg     (75张右相机图像, 1600×1600)
  ├── transforms.json     (150帧相机位姿 + 内参)
  └── config.yaml         (算法参数配置)

输出:
  ├── segement.pcd        (每个点标注了实例ID和语义类别)
  ├── removed.pcd         (去除家具后的纯结构点云)
  ├── floorplan.dxf       (带真实尺度的CAD平面图)
  └── floorplan.svg       (矢量图，含比例尺)
```

三个阶段的关系：

```
阶段一（逐张图像处理）
  "这张图里有什么？每个物体的轮廓在哪？"
      ↓ 输出：145张 mask + label
阶段二（逐帧融合到3D）
  "图里看到的这些物体，对应3D空间的哪些点？哪些是同一个物体？"
      ↓ 输出：3D实例分割点云 + 纯结构点云
阶段三（3D → 2D CAD）
  "结构点云从上往下看，墙在哪里？画出线段。"
      ↓ 输出：CAD平面图
```

## 二、输入数据说明

### 2.1 彩色点云 (colorized.pcd)

LiDAR扫描获得的三维点云，每个点包含 (x, y, z, r, g, b)。

**真实数据**：
- 总点数：**34,975,020**（约3500万）
- 空间范围：X ∈ [-62.94, 6.20]m, Y ∈ [-61.56, 32.70]m, Z ∈ [-1.57, 18.49]m
- 场景尺寸：约 **69m × 94m × 20m**（大型室内建筑，可能跨多层）
- 坐标单位：**米（m）**

### 2.2 多视角图像

在室内场景中，使用双目相机（左/右）拍摄的一系列图像。

- 左相机：70张，右相机：75张，共145张
- 分辨率：1600 × 1600 像素
- 格式：JPEG

### 2.3 相机位姿 (transforms.json)

每张图像对应一个4×4的变换矩阵（camera-to-world），描述拍照时相机在3D空间中的位置和朝向。

**真实数据示例**（第一帧）：

```
transform_matrix = [
  [ 0.9001,  0.0040, -0.4356,  0.0039]    ← 旋转 + 平移
  [-0.4355, -0.0104, -0.9001,  0.0260]
  [-0.0081,  0.9999, -0.0076, -0.0299]
  [ 0,       0,       0,       1     ]    ← 齐次坐标
]
```

这个矩阵的含义：
- 左上 3×3：旋转矩阵 R，描述相机的朝向
- 右侧 3×1：平移向量 t = (0.0039, 0.0260, -0.0299)m，描述相机在世界坐标系中的位置

### 2.4 相机内参 (config.yaml)

描述相机的光学特性（焦距、主点），用于3D点和2D像素之间的转换。

```yaml
image_width: 1600
image_height: 1600
camera_fx: 785.17    # x方向焦距（像素）
camera_fy: 785.30    # y方向焦距（像素）
camera_cx: 800.00    # 主点x坐标（像素）
camera_cy: 800.00    # 主点y坐标（像素）
```

**物理含义**：焦距 785 像素，在 1600×1600 图像上，对应约 **90° 的视场角**（FOV ≈ 2 × arctan(800/785) ≈ 91°）。

## 三、阶段一：2D开放词汇语义分割

### 3.1 目标

对每张输入图像，自动识别图中所有物体，并为每个物体生成：
1. **像素级分割mask**：哪些像素属于该物体
2. **语义标签**：这个物体是什么（如 "chair"、"floor"、"wall"）
3. **检测置信度**：模型对这个识别结果的确信程度

### 3.2 为什么叫"开放词汇"？

传统语义分割模型（如DeepLab、Mask R-CNN）只能识别训练时见过的固定类别（如COCO的80类）。但室内建筑场景中的物体种类非常多样——自动售货机、消防栓、柱子、电子屏幕等——很难预先枚举所有类别。

**开放词汇**意味着模型可以识别**任意文本描述的物体**，不受训练类别限制。这通过三个模型级联实现：

### 3.3 三模型级联流程

```
输入图像 (1600×1600)
    │
    ▼
┌─────────────────────────────────────────────┐
│  RAM (Recognize Anything Model)              │
│  输入：图像（缩放到384×384）                   │
│  输出：文本标签列表                             │
│  作用：告诉后续模型"这张图里可能有什么"          │
│                                              │
│  示例输出：                                    │
│  "bulletin board | pillar | floor | room |   │
│   mall | sign | vending machine"             │
└───────────────┬─────────────────────────────┘
                │ 文本标签
                ▼
┌─────────────────────────────────────────────┐
│  GroundingDINO (开放集目标检测)                │
│  输入：图像 + RAM输出的文本标签                 │
│  输出：检测框 (bounding box) + 置信度分数       │
│  作用：找到每个标签对应的物体位置                │
│                                              │
│  示例输出（NMS后）：                            │
│  box1: [4, 640, 673, 1479] "vending machine" │
│         置信度 0.63                           │
│  box2: [5, 5, 1595, 1593]  "room"            │
│         置信度 0.43                           │
│  box3: [1328, 3, 1598, 851] "bulletin board" │
│         置信度 0.42                           │
│  ... 共检测到7个目标                           │
└───────────────┬─────────────────────────────┘
                │ 检测框坐标
                ▼
┌─────────────────────────────────────────────┐
│  SAM (Segment Anything Model)                │
│  输入：图像 + 检测框（作为prompt）              │
│  输出：每个框对应的精确像素级mask               │
│  作用：从粗糙的框精确到像素级轮廓               │
│                                              │
│  示例：对"vending machine"的框                 │
│  → 输出206,400个像素的精确mask                 │
└─────────────────────────────────────────────┘
```

### 3.4 阶段一的输出格式

对每张图像生成两个文件：

**1. mask图像 (`*_mask.png`)**

一张与原图同尺寸的 uint16 灰度图（1600×1600），每个像素的值代表它属于哪个检测实例：

```
值 = 0  →  背景（1,481,721个像素）
值 = 1  →  第1个检测物体：vending machine（206,400个像素）
值 = 2  →  第2个检测物体：room/mall/store（205,182个像素）
值 = 3  →  第3个检测物体：bulletin board（129,821个像素）
值 = 4  →  第4个检测物体：soda（126,113个像素）
值 = 5  →  第5个检测物体：floor（372,713个像素）
值 = 6  →  第6个检测物体：sign/signage（23,521个像素）
值 = 7  →  第7个检测物体：electronic（14,529个像素）
```

**2. 标签文件 (`*_label.json`)**

每个检测实例的语义标签和检测框坐标：

```json
{
  "raw_tags": "bulletin board. pillar. floor. room. mall. sign. vending machine",
  "mask": [
    {"value": 0, "label": "background"},
    {"value": 1, "labels": {"vending": 0.63, "machine": 0.63},
     "box": [4.40, 640.46, 672.52, 1478.64]},
    {"value": 5, "labels": {"floor": 0.34},
     "box": [3.52, 966.07, 1594.71, 1596.83]},
    ...
  ]
}
```

其中 `box` 是 `[x1, y1, x2, y2]` 格式的检测框像素坐标，`labels` 是语义标签和置信度。

### 3.5 阶段一总体产出

- 处理 **145** 张图像
- 生成 **145** 对 mask + label 文件
- 每张图像检测到 **3-12** 个目标实例
- CPU 运行耗时：约 **2小时**（低内存版分阶段加载模型）

### 3.6 阶段一到阶段二的衔接

阶段二需要从阶段一获取的信息：

| 阶段一输出 | 阶段二如何使用 |
|-----------|--------------|
| mask图像（uint16） | 知道图像中哪些像素属于哪个物体 → 用于2D→3D反投影 |
| 语义标签 + 置信度 | 给3D实例赋予语义类别 → 用于贝叶斯融合和结构/非结构判断 |
| 检测框坐标 | 初步筛选有效检测（过小或过大的框被过滤） |

## 四、阶段二：3D语义实例融合（核心）

### 4.1 目标

将阶段一产生的 **145张2D语义mask** 融合到 **3D点云空间**，使得3500万个3D点中的每一个都被标注为某个**语义实例**（如"第3把椅子"、"大厅地板"、"左侧墙面"），最终将非结构类实例（家具等）从点云中移除，只保留建筑结构（墙、地板、天花板）。

**真实结果**：
- 总实例数：**278** 个
- 其中：floor 47个、ceiling 5个、wall 21个、chair 20个、door 8个 ...
- 被移除的点：**9,292,704** 个（占26.6%）
- 保留的结构点：**25,682,317** 个

### 4.2 核心挑战

为什么不能简单地把mask"贴"到点云上？

1. **一个3D物体被多帧看到**：同一把椅子可能出现在20张不同视角的照片中，每张照片里它的mask位置、大小、形状都不同。需要确定"这20个mask其实是同一把椅子"。

2. **遮挡**：有些点虽然在相机视野内，但被前面的物体挡住了，不应该被当前帧的mask标注。

3. **语义不一致**：同一个物体在不同帧可能被识别为不同的标签（第一帧说"carpet"，第二帧说"floor"，第三帧说"mat"），需要融合多帧信息确定最终类别。

### 4.3 整体流程（逐帧遍历150帧）

```
初始化：加载3500万点云 → 构建体素哈希索引
         ↓
对每一帧（150帧位姿逐个遍历）：
    │
    ├─ Step 1: 视锥体点云筛选
    │    "当前相机能看到哪些3D点？"
    │    → 输出：可见点集 + 每个点在图像上的(u,v)坐标
    │
    ├─ Step 2: 2D mask → 3D点集映射
    │    "mask里标记为'椅子'的像素，对应哪些3D点？"
    │    → 输出：每个detection对应的3D点索引集合
    │
    ├─ Step 3: 数据关联（3D点集级IoU）
    │    "这组3D点和之前已知的哪个实例是同一个物体？"
    │    → 输出：detection-实例匹配关系
    │
    └─ Step 4: 更新实例
         匹配到的 → 合并点集 + 更新语义标签
         未匹配的 → 创建新实例
         ↓
后处理：合并碎片实例 → 分类（结构/非结构）→ 移除家具点
```

下面逐步详细讲解，**所有数学公式都结合真实数据举例**。

---

### 4.4 Step 1：视锥体点云筛选

#### 问题

给定当前帧的相机位姿（4×4矩阵）和内参（焦距、主点），找出3500万个点中哪些能被这个相机"看到"。

#### 数学原理：针孔相机投影

将一个3D点 **P_world = (X, Y, Z)** 投影到图像上的像素坐标 **(u, v)**：

**第一步：世界坐标 → 相机坐标**

```
P_cam = T_world_to_cam × P_world
```

其中 T_world_to_cam 是 transforms.json 里变换矩阵的逆（因为 transforms.json 存的是 camera-to-world）：

```
T_world_to_cam = T_cam_to_world⁻¹
```

**第二步：相机坐标 → 像素坐标**

```
u = fx × (X_cam / Z_cam) + cx
v = fy × (Y_cam / Z_cam) + cy
```

用真实数据举例：

```
已知相机内参：fx=785.17, fy=785.30, cx=800, cy=800

假设一个3D点在相机坐标系下为 P_cam = (1.5, -0.8, 3.0)m

投影计算：
  u = 785.17 × (1.5 / 3.0) + 800 = 785.17 × 0.5 + 800 = 1192.6
  v = 785.30 × (-0.8 / 3.0) + 800 = 785.30 × (-0.267) + 800 = 590.6

像素坐标 (u, v) = (1193, 591)

判断是否可见：
  0 ≤ u < 1600 且 0 ≤ v < 1600 → ✅ 在图像范围内
  Z_cam = 3.0 > 0            → ✅ 在相机前方

结论：这个3D点在当前帧可见，投影到图像的 (1193, 591) 位置。
```

#### 暴力方法的问题

对3500万个点逐一做上述投影计算：
- 每个点：1次矩阵乘法 + 2次除法 + 4次比较 ≈ 20次浮点运算
- 3500万 × 20 = **7亿次运算/帧**，150帧 = **1050亿次**

这太慢了。

#### 体素哈希加速

**核心思想**：不逐个点检查，先按空间区域粗筛。

1. **建立体素索引**：将3D空间划分为 2.4m × 2.4m × 2.4m 的格子（体素），每个体素记录其中包含哪些点的索引。

```
体素坐标 = (floor(X/2.4), floor(Y/2.4), floor(Z/2.4))

例：点 P = (-50.3, 20.1, 5.7)
→ 体素坐标 = (floor(-50.3/2.4), floor(20.1/2.4), floor(5.7/2.4))
           = (-21, 8, 2)
```

用哈希函数将体素坐标映射到哈希表：
```
hash(-21, 8, 2) = ((-21 × 73856093) ⊕ (8 × 19349663) ⊕ (2 × 83492791)) & 0x7FFFFFFF
```

2. **DDA视锥体遍历**：用 Digital Differential Analyzer 算法，只遍历相机视锥体穿过的体素格子（类似光线追踪），跳过大量无关区域。

**加速效果**：

```
暴力方法：遍历 34,975,020 个点
体素加速：遍历 ~1,000 个体素 → 约 900,000 个候选点 → 精确投影验证

加速比：约 40倍
```

3. **可见性检测**：候选点中，有些虽然在视锥体内，但被前面的物体遮挡。使用球面翻转（Ball Pivoting）+ 凸包算法剔除被遮挡的点。

**最终输出**（以真实数据为例，某一帧）：

```
视锥体内体素数量：1,088
视锥体内候选点数量：912,289
精确投影验证后：842,270 个可见点
凸包可见性检测后：481,127 个真正可见的点

同时得到每个可见点在图像上的投影坐标 (u_i, v_i)
```

---

### 4.5 Step 2：2D mask → 3D点集映射

#### 目标

将阶段一的 mask 图像和 Step 1 得到的投影结果关联起来。

#### 过程

对当前帧的每个 detection k（例如"vending machine"，mask 值=1）：

```
detection_points[k] = {}   // 空集合

对每个可见点 i（共 481,127 个）:
    (u_i, v_i) = 该点在图像上的投影坐标
    mask_value = mask图像在 (u_i, v_i) 处的像素值
    
    如果 mask_value == k:
        detection_points[k].add(i)    // 点 i 属于 detection k
```

**真实数据举例**：

```
当前帧检测到7个物体：

detection 0: "vending machine"  → mask值=1
  mask区域覆盖 206,400 个像素
  可见点中有 23,456 个点的投影落在这个mask区域内
  → detection_points[0] = {点索引集合, 大小=23,456}

detection 1: "floor"  → mask值=5
  mask区域覆盖 372,713 个像素
  可见点中有 187,234 个点的投影落在floor区域
  → detection_points[1] = {点索引集合, 大小=187,234}

detection 2: "bulletin board"  → mask值=3
  → detection_points[2] = {点索引集合, 大小=8,912}

... 以此类推
```

**关键理解**：现在每个2D检测已经有了一组3D点——"这些3D空间中的点，看起来像是自动售货机"。但这只是**当前帧的观测**，同一个自动售货机在其他帧也会被看到，需要通过数据关联把它们合并。

---

### 4.6 Step 3：数据关联——3D点集级IoU（核心创新）

#### 问题

```
当前帧的 detection_points[0] 有 23,456 个点，看起来是"vending machine"
已知全局实例列表中 instance_42 也是 "vending machine"，包含 45,000 个点

问：detection_points[0] 和 instance_42 是同一台售货机吗？
```

#### 传统方法（2D IoU）的问题

传统方法在2D图像平面上比较：

```
IoU_2D = |mask_A ∩ mask_B| / |mask_A ∪ mask_B|

其中 mask_A = 当前检测的mask
     mask_B = 已知实例投影到当前图像上的mask
```

**问题**：如果相机从左边拍，售货机在图像右侧；从右边拍，售货机在图像左侧。两个mask在图像上**完全不重叠**，IoU_2D = 0，关联失败！但它们明明是同一台售货机。

#### 本文方法（3D点集IoU）

直接在3D点索引空间计算重叠：

```
设 A = detection_points[0] = {p1, p2, p3, ..., p23456}   // 当前帧看到的点
   B = instance_42.cloud_indices = {q1, q2, q3, ..., q45000}  // 已知实例的所有点

IoU_3D = |A ∩ B| / |A ∪ B|

其中 A ∩ B 是两个集合的交集（共同包含的点索引）
     A ∪ B 是两个集合的并集
```

**真实数据举例**：

```
A = 当前帧看到的"vending machine"点集，23,456个点索引
B = 已知实例 instance_42 的点集，45,000个点索引

交集：A ∩ B = 18,234 个共同点索引
并集：A ∪ B = 23,456 + 45,000 - 18,234 = 50,222

IoU_3D = 18,234 / 50,222 = 0.363

阈值 min_iou = 0.3

0.363 > 0.3 → 判定为同一实例，关联成功！
```

**为什么3D IoU有效**：同一台售货机占据的3D空间是固定的，无论从哪个角度拍，映射到的3D点集都会有大量重叠。3D IoU对视角变化天然鲁棒。

#### 双向最大匹配

当有K个新检测和M个已知实例时，构建 K×M 的IoU矩阵，采用双向一致性匹配：

```
假设 K=7 个检测，M=50 个活跃实例

IoU矩阵 (7×50)：
                inst_1  inst_2  inst_3 ... inst_50
detection_0:    0.363   0.01    0.00   ... 0.02
detection_1:    0.00    0.00    0.45   ... 0.00
detection_2:    0.00    0.38    0.00   ... 0.00
...

列方向匹配：对每列（每个实例），找IoU最大的行（检测）
  inst_1 → detection_0 (IoU=0.363 > 0.3) ✓
  inst_3 → detection_1 (IoU=0.45 > 0.3)  ✓

行方向匹配：对每行（每个检测），找IoU最大的列（实例）
  detection_0 → inst_1 (IoU=0.363 > 0.3) ✓
  detection_1 → inst_3 (IoU=0.45 > 0.3)  ✓

双向一致（assignment值=2）才确认匹配。
如果某个检测没有匹配到任何实例 → 创建新实例。
```

#### 歧义处理

如果一个检测与多个实例都有较高IoU（可能是过分割），记录为"歧义对"，后续用3D空间的IoU进一步判断是否需要合并这些实例。

---

### 4.7 Step 4：实例更新与贝叶斯语义融合

#### 匹配到已有实例

```
已知：detection_0 (23,456个点, 标签 "vending machine" 置信度0.63)
      匹配到 instance_42 (原有45,000个点)

操作1：合并点集
  instance_42.cloud_indices = instance_42.cloud_indices ∪ detection_0.points
  = 45,000 + 23,456 - 18,234(重叠) = 50,222 个点

操作2：更新语义标签
  instance_42.measured_labels["vending"] += 0.63
  instance_42.measured_labels["machine"] += 0.63
  
  经过N帧累加后，标签分数最高的就是最终预测类别。
```

#### 创建新实例

如果某个 detection 没有匹配到任何已有实例（IoU 都低于阈值），创建新实例：

```
instance_278 = new Instance(
    id = 278,
    cloud_indices = detection_points[k],    // 当前帧看到的点
    labels = {"chair": 0.52},               // 初始标签
    frame_id = 当前帧号
)
```

#### 贝叶斯语义融合（设计中）

简单累加的问题：RAM输出的标签噪声大，"floor"和"carpet"和"mat"可能指的是同一个东西。

贝叶斯方法通过一个**似然矩阵** P(measurement | class) 将开放词汇标签映射到预定义类别：

```
预定义类别：[floor, ceiling, wall, door, window, chair, table, ...]

似然矩阵示例：
                 floor   ceiling  wall   chair  ...
RAM输出"floor"    0.8     0.01    0.01   0.0    
RAM输出"carpet"   0.6     0.0     0.0    0.0    
RAM输出"mat"      0.5     0.0     0.0    0.0    
RAM输出"ceiling"  0.01    0.8     0.01   0.0    
RAM输出"chair"    0.0     0.0     0.0    0.8    

贝叶斯更新：
  P(class | 观测1, 观测2, ...) ∝ P(class) × ∏ P(观测i | class)

例：某实例在5帧中被标记为：
  帧1: "carpet" (0.34)
  帧2: "floor" (0.46)
  帧3: "mat" (0.43)
  帧4: "floor" (0.41)
  帧5: "carpet" (0.38)

累加融合后 floor 类的似然最高 → 最终判定为 floor
```

### 4.8 后处理

#### 地板/天花板合并

由于地板和天花板面积大，通常被分成多个碎片实例。统计所有预测标签含"floor"的实例，基于3D空间连通性合并为一个整体。

**真实数据**：47个 floor 碎片 → 合并后 1 个地板实例（含根地板 328,008 点）

```
Merging 52 ceiling instances
Root floor has 328,008 points
48 ceiling instances are checked
Merged 47 ceiling instances
```

#### 重叠实例合并

用3D IoU检查所有实例对，合并高度重叠的实例：

```
Merged 61/339 instances by 3D IoU. It takes 1804.9 ms.
```

339个原始实例 → 合并后 **278** 个。

#### 移除非结构实例

根据语义标签，将实例分为"结构"和"非结构"：
- 结构：floor, ceiling, wall, pillar, beam, door, window, stair → **保留**
- 非结构：chair, table, vending machine, sign, ... → **移除**

从原始点云中删除非结构实例的所有点索引：

```
原始点云：34,975,020 点
移除家具等非结构点：9,292,704 点（26.6%）
保留结构点云：25,682,317 点 → 输出为 removed.pcd
```

## 五、阶段三：自适应点云投影与CAD线段提取

### 5.1 目标

从阶段二输出的结构点云 (removed.pcd, 2568万点) 中提取墙体的2D平面图。

核心思想：**从上往下看**，墙体是垂直面，投影到水平面上就是线段。

### 5.2 Step 1：地板分离与坐标对齐

使用 RANSAC 从结构点云中拟合地板平面，并将坐标系旋转使地板法线朝上（Z轴）：

```
RANSAC 平面拟合：
  输入：25,682,317 个点
  输出：地板平面方程 ax + by + cz + d = 0
        法线向量 n = (a, b, c)
  
分离结果：
  地板点：8,873,170 个
  非地板点（墙体等）：16,809,147 个

坐标对齐：
  Step 1: 将地板法线旋转到Z轴正方向
  Step 2: 将墙体主方向旋转到X轴方向（PCA求主轴）
```

### 5.3 Step 2：自适应高度检测（创新点）

**问题**：需要选择水平切片的高度范围来投影墙体。不同建筑、不同楼层高度完全不同。

**方法**：对旋转后的墙体点云建立Z轴直方图（100个bin），自动检测地板和天花板：

```
真实数据的Z轴直方图（旋转后）：

bin[3]  Z=[-1.03, -0.83]:  1,145,916 pts  ← 地板（最低密集峰）
bin[4]  Z=[-0.83, -0.63]:  2,179,287 pts
bin[13] Z=[ 0.97,  1.17]:    342,833 pts  ← 墙体区域
bin[14] Z=[ 1.17,  1.37]:    368,076 pts
...
bin[19] Z=[ 2.18,  2.38]:    619,963 pts
bin[42] Z=[ 6.79,  6.99]:    688,344 pts  ← 可能是第二层
bin[65] Z=[11.40, 11.60]:  1,020,591 pts
bin[66] Z=[11.60, 11.80]:    872,126 pts  ← 天花板（最高密集峰）

自动检测结果：
  地板高度 ≈ -0.83m
  天花板高度 ≈ 11.60m
  切片范围 = [-0.83 + margin, 11.60 - margin] = [0.41, 10.36]m
  margin = max(10% × (11.60 - (-0.83)), 0.2) ≈ 1.24m
```

对比硬编码参数的灾难性后果：

| 参数 | 投影有效像素 | 检测墙线数 |
|------|------------|-----------|
| 硬编码 [-1.5, -1.0] | 3,625 | 5 条 |
| 自适应 [0.41, 10.36] | 55,000+ | 79 条 |

### 5.4 Step 3：多层切片投票

将 [0.41, 10.36]m 的高度范围等分为 **10层** 切片，每层独立投影到2D栅格：

```
切片高度 = (10.36 - 0.41) / 10 = 0.995m/层

第1层: Z ∈ [0.41, 1.41]  → 投影到2D → 二值图 slice_00.png
第2层: Z ∈ [1.41, 2.40]  → 投影到2D → 二值图 slice_01.png
...
第10层: Z ∈ [9.37, 10.36] → 投影到2D → 二值图 slice_09.png
```

**投票规则**：某个2D像素被 ≥ minVotes 层命中，才认为该位置有墙体。

```
minVotes = 2:  一个像素只要在10层中有2层出现 → 保留
               → 55,000+ 有效像素，保留了绝大部分墙体

minVotes = 6:  必须在10层中有6层出现 → 过于严格
               → 只有 3,625 像素，丢失了99.3%的墙体信息
```

### 5.5 Step 4：栅格化与2D坐标系

将16,809,147个非地板点的 (X, Y) 坐标映射到2D栅格图像：

```
effectiveGridSize = 0.025m (每像素代表2.5cm)

2D点云范围：X ∈ [0, 90.10]m, Y ∈ [0, 59.64]m

栅格图像尺寸：
  rows = ceil(90.10 / 0.025) = 3606 像素
  cols = ceil(59.64 / 0.025) = 2387 像素

坐标映射：
  pixel_row = floor((X - X_min) / 0.025)
  pixel_col = floor((Y - Y_min) / 0.025)

例：3D点 (45.0, 30.0, 5.0)
→ pixel = (floor(45.0/0.025), floor(30.0/0.025)) = (1800, 1200)
```

### 5.6 Step 5：线段检测与合并

```
投票后的二值图 (3606×2387)
    │
    ├─ 形态学闭操作（连接小间隙）
    ├─ 高斯平滑 + 二值化
    │
    ▼
骨架化 (Zhang-Suen thinning)
    │ 把宽线条变成单像素宽的骨架线
    │
    ▼
HoughLinesP 直线检测
    │ threshold=30, minLineLength=20, maxLineGap=10
    │ 检测到 149 条原始线段
    │
    ▼
共线碎片合并（无Manhattan约束）
    │ 角度差 < 8°，垂直距离 < 15px，间隙 < 35px
    │ 用 cv2.fitLine 拟合合并后的线段
    │ 149 → 115 → 去重后 79 条
    │
    ▼
输出：79条墙体线段 + DXF/SVG（米制坐标）
```

### 5.7 像素坐标 → 真实尺度

最终输出的线段需要从像素坐标还原为米制坐标：

```
线段像素坐标：(px1, py1) → (px2, py2)
               ↓
真实坐标：(px1 × 0.025, py1 × 0.025) → (px2 × 0.025, py2 × 0.025)

例：某墙线像素坐标 (100, 500) → (100, 1100)
→ 真实坐标：(2.5m, 12.5m) → (2.5m, 27.5m)
→ 这是一面长 15m 的墙

实际检测结果统计：
  场景总尺寸：59.7m × 90.2m
  检测墙线：79条
  墙线总长度：241.0m
  最长墙线：15.9m
  最短墙线：0.7m
  分辨率：2.5 cm/像素
```

### 5.8 输出格式

| 文件 | 格式 | 用途 |
|------|------|------|
| v3_step5_final_scaled.png | PNG | 带比例尺和网格的可视化图 |
| floorplan.dxf | DXF R12 | AutoCAD/Revit可直接打开，米制坐标 |
| floorplan.svg | SVG | 矢量图，浏览器可查看，带5m比例尺 |

DXF文件中每条线段记录的是真实的米制坐标：
```
LINE
  图层: WALLS
  起点: (2.500, -12.500, 0.000)
  终点: (2.500, -27.500, 0.000)
```
